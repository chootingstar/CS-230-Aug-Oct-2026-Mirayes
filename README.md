A repository for CS 230 class

Briefly summarize The Gaming Room client and their software requirements. Who was the client? What type of software did they want you to design?

The Gaming Room asked for help creating environment software for their game Draw It or Lose It based on an old television show of the same name.

What did you do particularly well in developing this documentation?

Identifying structures for speedy operations once the game is up and running.

What about the process of working through a design document did you find helpful when developing the code?

My thoughts of what to do shift in focus and ideas based on what I discuss. Creating a baseline idea of what I want in the documentation is helpful.

If you could choose one part of your work on these documents to revise, what would you pick? How would you improve it?

I would improve on the research into using different operating systems and devices. As much as I found great resources for them, 
I know there is a vast number more options to choose from with possibly better usage for the client. Being up to date with resources
available just happens to be a weakness of mine at this time.

How did you interpret the user’s needs and implement them into your software design? Why is it so important to consider the user’s needs when designing?

When it comes to the needs of a user, I need to consider what they see and attempt. When it came to memory management pulling up the pictures for the game
I considered the fact that the user does not know what comes next nor should. And that they want to have their game function swiftly to keep the game
going. So I only needed to have a few pictures being handled by memory at any given time.

How did you approach designing software? What techniques or strategies would you use in the future to analyze and design a similar software application?

My main approach is asking what I want to do and how do I plan to get there. For simple example, I want to tell every even number from 1 to 10. 
I consider that I must have the computer look at every even number along the way to 10 and print it. How I design it to recognize that can go one
of two ways, either have the computer "hop" on all the even numbers or check each number if it is even. For future software applications similar to
the Draw It or Lose It environment, I would research the latest libraries for connecting over HTTP with the most security patches. With my main strategy 
being that when I create part of the code I ask how can I break it so I can fix it. A combination of tool preparation and a form of pen testing.
